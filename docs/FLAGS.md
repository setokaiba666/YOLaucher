# Server flags (generated)

> English reference of the server feature flags. The authoritative list is `tools/yo2emu/yo2srv/BANDERAS.md` (Spanish),
> generated by `python -m yo2srv.gen_banderas` from the registry in `tools/yo2emu/yo2srv/config.py`; the unit tests
> check that it is up to date. If they differ, the generated file and `config.py` win.

197 flags. Default profile: `vanilla` (`YO2_PERFIL=vanilla|enhanced`). Currently `enhanced` = `vanilla` for every flag
(`enhanced` is shown as "= vanilla"). Precedence at startup: profile → `admin_banderas.json` → `YO2_*` environment
variable → hot change at runtime.

| Origin | Flags | Meaning |
|---|---:|---|
| `oficial` | 125 | behaves like the original game (C/P in the research notes) or is an attempt to |
| `inventado` | 13 | our own addition, behind a flag (not 1:1 with the original) |
| `tecnico` | 39 | no gameplay effect: paths, ports, limits, logs, tests, security |
| `?` | 20 | origin undecided (see below) |

### Launcher administration

The Host form exposes the documented startup controls `YO2_TOURNAMENT`,
`YO2_EVENTS`, `YO2_AUTO_CLOCK` and `YO2_DPAUTH` through typed controls.
Changes marked as startup-only apply after stopping and starting the server.

While a server is running, Manage exposes authenticated localhost endpoints
for DUELPASS codes (`/gestion/duelpass*`) and the existing CHAMPIONSHIP
implementation (`/gestion/torneo`). Codes are generated using the same
`research/persistencia/duelpass.py` store as the game and every mutating
operation is written to the admin audit log.

Starting, announcing, pausing, resuming and ending an event are runtime
operations and do not require restarting `run.py`. Startup switches such as
`YO2_TOURNAMENT`, `YO2_EVENTS`, `YO2_AUTO_CLOCK` and `YO2_DPAUTH` are read
when the server starts; changing those switches requires stopping and
starting the server.
